This release is for everyone who streams games or a desktop with Punktfunk. It works with 0.34.x, so everything you have already paired keeps working, and you can update one side at a time — with one exception on Windows, where the host and its display driver now have to match. They ship in the same installer, so updating normally is all it takes. Read "Before you update" if your host runs Windows or if you use the shared clipboard on Android.

The headline is that Punktfunk now runs **in a browser**. Open a page, pair it like any other device, and stream — no install, on a machine you do not own or cannot install software on. It is a separate app in its own repository and it is early, but the streaming underneath it is the same code every other client uses.

On Windows the whole capture path was rebuilt. **Video encoding now happens inside the display driver**, which is what lets a stream survive things that used to freeze it: a UAC prompt, a lock screen, a wedged encoder. The host also watches its own capture now and repairs it in stages instead of dropping the session, and it will tell you on the Status page what it saw and what it did about it.

And the game library grew a lot: play time and last-played on every title, a settings profile you can pin to one game, and **six new places games are found** — Ubisoft Connect, Amazon Games, Battle.net, your desktop's own applications and Flatpaks, Bottles and itch.io.

## TL;DR

- **Punktfunk runs in a browser.** No install, pair it like any other device.
- **Windows: the encoder moved into the display driver.** UAC prompts and lock screens no longer freeze the picture, and a stalled capture repairs itself instead of ending the stream.
- **Windows gets brand-new installers**, ours rather than Inno Setup, with a real wizard. Your existing install upgrades in place and every silent flag still works.
- **Six new game sources**: Ubisoft Connect, Amazon Games, Battle.net, desktop apps and Flatpaks, Bottles, itch.io. Plus play time, last-played, and a settings profile per game.
- **Stream straight from Steam's Play button** on a Steam Deck, through the Decky plugin.
- **Trackpad scrolling was about five times too fast on every platform.** It is now the distance your finger actually moved.
- **AMD: the green screen at 4K120 and the flickering black bars are both fixed.** Update your client.
- **Android: clipboard sharing is now off by default.** Turn it back on per host if you used it.

## Before you update

- **Windows hosts: the host and its display driver must now be the same version.** The encoder lives inside the driver from this release, so a host from one release cannot drive a driver from another — a mismatch ends the session with an error naming both versions. They ship in one installer, so a normal update handles it. Two things to expect: applying the update flaps the virtual display, so budget a brief black screen, and if an upgrade skips the driver the installer now warns you rather than leaving you to find out mid-session.
- **Android: the shared clipboard is off by default for new hosts.** Text you copy on the phone no longer reaches a host you pair from now on until you switch it on for that host. Hosts you had already paired keep whatever you set. This is a deliberate change: clipboard contents are the kind of thing that should be opted into rather than out of.
- **Linux, if you install unattended: `--yes` now joins the `punktfunk` group on every distribution**, not only Bazzite and Nobara. The group is what grants USB passthrough. Pass `--no-punktfunk-group`, or set `PUNKTFUNK_INSTALL_PUNKTFUNK_GROUP=0`, if you do not want that on your desktops.
- **Linux, if you script installs: `scripts/install.sh` is now a small download stub.** It fetches the real installer, checks its hash and runs it. If you vendored or sourced the old script, call the published binary instead.
- **Windows, if you install with winget:** the host package is now an `exe` installer rather than an Inno one. `winget upgrade` keeps tracking the same product, so this should pass unnoticed — it is written down here in case it does not.

## New

- **A browser client.** Punktfunk's console and its video now run on a web page: the interface is the same one the desktop app draws, compiled for the browser, and the video arrives over WebTransport. Everything that makes a stream private — pairing, encryption, the loss recovery — is the same code the native clients run. You pair a browser once, with a key the browser generates and keeps, and it proves that key each time it connects. It lives in [its own repository](https://github.com/punktfunk/client-web) and is early: treat it as something to try rather than something to rely on. **On the host it is off until you turn it on** with `--webtransport`, and you should name the pages allowed to reach it with `PUNKTFUNK_WEBTRANSPORT_ORIGINS`, because browsers do not apply the usual same-origin rule to this kind of connection.
- **Six new places your games are found.** Ubisoft Connect, Amazon Games and Battle.net on Windows; your desktop's own applications and Flatpaks, Bottles, and itch.io on Linux, with itch.io on Windows too. They install from the console's **Game sources** page. One quirk worth knowing: a Battle.net that is not already running only opens itself the first time you pick a game, so keep it running or pick the tile twice.
- **Play time and last-played on every title.** A game you have launched through Punktfunk records when you last played it, how long you have played, and how long the last session ran. Nothing is recorded until you launch something, and it stays on the host.
- **A settings profile pinned to one game.** Raise **Options** on a cover and pick **Settings profile…** to bind a profile to that title, so a game that wants a different bitrate or codec gets it without you changing anything by hand. Settings resolve in the order one-off ▸ this title ▸ this host ▸ your defaults. Delete the profile and the title quietly falls back to the host's.
- **Picking a game now shows you it is happening.** The cover lifts out of the shelf, turns once, and holds in the middle of the screen until the host reports the game as running — over the connecting dial and then over the stream itself. Press anything to skip to the picture. It gives up on its own if the host never gets there.
- **A shelf can connect without launching anything.** The Options menu's first row is now **Resume <title>** while the host has a game up, or **Connect to <host>** when it does not. It is the only way back into a game the host started by itself, and every shelf now leads with a Desktop card that does the same thing.
- **Stream from Steam's own Play button.** The Decky plugin puts your Punktfunk hosts in the ▾ menu beside Play on a game's Steam page, re-labels the button as **Stream** while a host is chosen, and runs the stream under a shortcut carrying the game's own name, art and icon — so it looks right on the Recent shelf afterwards, and ending the stream returns you to the game's page.
- **Every client shows what a host is playing.** A host tile names the game that host currently has up, so you can tell a machine that is free from one that is mid-session before you connect.
- **Android decodes PyroWave.** A phone or tablet with a recent enough Vulkan device now decodes our low-latency codec directly on the GPU. Nothing to set: the codec is still chosen per session, and a device that cannot do it never offers it.
- **Android splits at a foldable's hinge.** A book-style foldable half-opened on a table puts the picture on the upright half and the on-screen controller on the flat one, so your thumbs are never on top of the game. Fold it flat and the picture fills the screen again.
- **The macOS app gets the quick-action ring**, which until now was only on the phone, tablet and TV clients.
- **Windows clients can turn on DualSense haptics and pad speaker** from settings. Both worked before but could only be reached by editing a settings file.
- **The Steam Controller 2 streams over USB from a Mac**, including through the Puck dongle, where it was Bluetooth-only. Each part of the controller arrives as its own pad, the way it does when plugged in locally.
- **`guide` and `qam` buttons on the quick-action ring**, which tap the host pad's own system buttons — the Steam overlay and the quick-access menu, without a controller in your hands.
- **The on-screen controller can be rearranged.** Move, resize or hide each stick, D-pad, face cluster, shoulder and trigger independently, with a separate layout for narrow screens.
- **Omarchy gets a proper integration.** A bar widget ships with the host package, the panel is now Now / Displays / Stats tabs with sparklines, your saved hosts appear in the Omarchy menu, host actions get their own menu, and the clients follow the Omarchy theme as it changes.
- **New command-line verbs**: `summary` says who is streaming, `stats` gives live bitrate, drops and timing percentiles, `display` reads and switches the virtual display preset, and `default-host` sets the host that `launch` and `library` use when you do not name one.
- **The Linux installer chooses what to install.** `--host` and `--client` pick a side, so a machine that only ever watches can install just the client — including on distributions with no Punktfunk repository, where it falls back to a Flatpak. SteamOS is now a supported family rather than a refusal. Every host install also trusts the console's certificate, so the web console opens without a browser warning; `--no-console-cert` opts out.
- **A Windows host for ARM64** (Snapdragon X), as a canary build. It streams video only and has not been run on real hardware yet: Steam ships no ARM64 audio driver, so there is no game audio or microphone until one exists.
- **A multi-seat add-on contract.** Two people can use one Windows machine at the same time, each with their own session, displays and audio. It is opt-in, ships separately, and nothing changes on a machine that does not have it.

## Improved

- **Windows tells you what its capture is doing.** The console's session card now shows whether capture is healthy, idle, suspect, stalled, recovering or on the secure desktop, what evidence led to that, which encoder the driver opened, and what the last repair attempt did. A freeze is something you read off the page instead of something you grep out of a log.
- **A stalled Windows capture repairs itself in stages.** Instead of ending the session, the host tries the smallest fix first — restart the encoder, then the swapchain, then presentation, then cycle the driver — and each step has to prove itself with real frames before it counts. It gives up gracefully rather than looping: four attempts per ten minutes, with a cooldown that doubles.
- **The Windows installers are ours now.** Both the host and the client install through a wizard we wrote — Recommended or Custom, a real stepper, the web console password shown once behind a reveal, and next steps on the last page — instead of Inno Setup. Nothing a script or an installed machine depends on changed: the same silent flags, the same entry in Add/Remove Programs, the same uninstaller, the same install directory, the same signature. An older install upgrades in place. The wizard needs Windows 11; a silent install still runs anywhere the host does.
- **The Linux installer asks less and knows more.** Package managers no longer ask their own "proceed?" — running the installer is the consent — and a step's output stays hidden unless it fails. The install commands are now generated from the same file the website reads, so the documentation and the installer cannot drift apart. `--demo` walks the entire flow against a fake machine, changing nothing, if you want to see what it would do.
- **The overlay sizes itself for the room.** The stats display and the quick-action ring draw larger on an Android TV, where the screen is across the room rather than in your hands, and you can step the overlay size mid-stream.
- **Real-time GPU priority is the default again on Windows**, in both the host and the display driver, rather than something that had to earn its way up a ladder.
- **SteamOS hosts carry their own copy of FFmpeg.** SteamOS moves its media libraries independently of anything we can pin against, which is how a host that built cleanly could then refuse to start. The first install takes about four minutes longer and updates reuse the build.
- **A pinned data port still gets a hole punched through it.** Setting the port used to quietly disable the NAT traversal that makes connections work from outside your network.
- **Diagnostics from the Windows driver land in the normal host log**, instead of needing a debug switch and a file in a system account's temp directory.
- **webOS TVs get the interface they need.** The bitrate slider stops at a number the TV can actually decode, codecs its decoder cannot handle are no longer offered, Back at the top level asks before quitting, the controller-friendly interface switch is available, and hovering moves the focus.

## Fixed

- **AMD clients: everything below the top of the picture turned green at 4K120.** We were describing where each tile of an AV1 frame starts in the wrong unit. Most drivers recalculate it and never noticed; AMD's reads what we sent. Update your client.
- **AMD clients: flickering black bars down one edge.** The picture was being cleared and drawn in the wrong order, so the two raced. It affected every codec.
- **Trackpad scrolling ran away on every platform.** A finger's travel was priced as wheel clicks, and then every host expanded each of those clicks into a full scroll step — roughly five times too far, and worst on a Mac, where all scrolling is precise. Clients now say when a scroll came from a trackpad, and hosts scroll the distance your finger moved.
- **A grey smear that lasted until the next scene change.** After packet loss, a frame whose reference chain the decoder had patched over could still be shown, and nothing asked for a repair. Such a frame is now held back and a fresh keyframe requested. Separately, NVENC hosts were only invalidating the frames the client named as lost, so the repair frame could itself be predicted from a damaged one.
- **Windows: UAC prompts, the lock screen and sign-in froze the picture.** The stream held the last ordinary-desktop frame until you resized the client window. Those screens now render as they happen.
- **Windows: the mouse pointer froze on the client** while the rest of the desktop kept moving. Moving a pointer is not a change the desktop reports as damage, so nothing triggered a new frame.
- **Windows: the pointer was three times too large** on a host started on a scaled desktop. The host now follows the display's real scale from launch.
- **Windows clients crashed on the first text drawn** on machines with a Visual C++ runtime older than 14.40. The client now carries its own copy, and it also ships its icon font, which was missing from installed builds and left blank squares where glyphs should be.
- **Windows: a crash now says what crashed.** The client log records the exception, the address and the faulting component instead of a bare negative number, and the "Couldn't connect" banner says it was a crash.
- **Windows: a session died at startup if you had set a refresh-rate multiplier.** The display is now created at the multiplied rate directly.
- **Windows: HDR with full colour detail silently lost the colour detail**, and games launched from Punktfunk started in the host service's own folder rather than their own, which some games refuse outright.
- **Two controllers swapped rumble, touchpads and pad audio.** The host assigns pad slots as pads first move, and one plane of input was never translated into that numbering — so each pad drove the other's device, and with two people connected a DualSense could play the other session's audio.
- **Adaptive triggers did nothing on a virtual DualSense.** Games check a status field, not the trigger position, and the host was leaving it empty — so with adaptive triggers switched on, R2 stopped working in games that use them.
- **Android: a Steam Controller 2 over Bluetooth barely worked.** Every message was written to whichever channel was found first, rather than the specific one each belongs to, so lizard mode never switched off, only one motor could be reached, and the gyro never turned on. A controller that powers off mid-session is also picked back up now.
- **Apple: sound sat up to 90 ms behind the picture with the microphone off**, and cut out every half-minute with it on. The client now asks for a small audio buffer either way, and no longer mistakes the start of its own audio engine for a failure.
- **Apple TV: 4:2:0 streams use the system video renderer** on tvOS 17.4 and newer, which removes a two-refresh delay the previous path reserved. Older systems, 4:4:4, PyroWave and Smoothness keep the old renderer.
- **A sleeping host looked online, and Wake-on-LAN never fired.** A host that suspends does not announce that it is going, and its network advert can linger for over an hour, so every client believed it was awake. Presence is now an actual reachability check on all six clients.
- **A second game launch either did nothing or killed the first.** The stream now uses one compositor per seat and ends when the game actually ends, rather than on a process scan that could mistake Steam's own install step for the game.
- **KDE: the streamed screen sat off to one side of the desktop**, which put the launcher and the desktop menu partly off-screen. Its capture also negotiates one more buffer, closing a tear under load.
- **A switched-off screen that woke itself mid-stream** cost the stream a rebuild every time. It is now parked for the session and restored when you disconnect. A game's own resolution also survives the host re-asserting its display layout, and a stream rebuilt after a capture loss replaces the stalled screen rather than adding a second one beside it.
- **AMD Polaris and Vega hosts failed every session.** Our encoder demanded a newer AMD runtime than that driver branch will ever ship. The floor is now 1.4.30.
- **The pointer forwarded to a scaled Linux desktop was drawn too large** — 2.25 times at 150% scaling — because the scale was applied twice.
- **Every connected controller drives the desktop launcher**, not only the most recently connected one, and the same on a Steam Deck in Gaming Mode.
- **The quick-action ring follows your thumb** on Apple and Android instead of stepping one slot at a time, and on Apple TV the Siri Remote drives it properly — swipe to move, click to fire, Back to close. Menu also backs out of every tvOS screen it used to get stuck on.
- **Pairing notifications appear once, when someone actually knocks**, instead of replaying old ones each time the console opened.
- **Re-running the Linux installer upgrades a broken install** instead of skipping the packages because they were all present, and switching release channels keeps and removes the right packages instead of stripping them.
- **The host and the client can be installed on the same Arch machine** — they were fighting over a shared icon.
- **A SteamOS box stopped rebuilding the host on every single boot** after one failed rebuild check.
- **Mac keyboard shortcuts pass through in desktop mouse mode**, matching the other clients.
- **Log noise removed**: a false warning about audio format on every ordinary session, and a clamped refresh rate that used to pass by as an information line now warns and names the rates the display offered.

## For developers

Protocol, application binary interface (ABI), driver and embedder detail is in [the v0.35.0 CHANGELOG](https://git.unom.io/unom/punktfunk/src/tag/v0.35.0/CHANGELOG.md). It carries the version table and the full breaking-change list.

The short version: **the streaming protocol and the C ABI both stand still**, at 2 and 28. What moves is the **Windows virtual-display driver protocol, 6 to 8**, and its minimum moves with it — video encoding now happens inside the driver, and every object it hands out belongs to the host process that created it, so a host and a driver from different releases have nothing in common to talk over. They ship in one installer.

Also worth knowing: the SDK is `@punktfunk/host` **0.2.0** and runs in a browser now, with `@punktfunk/host/core` carrying nothing Node-specific and a credential seam that covers both a static bearer token and a paired browser's device key. The plugin kit is **0.4.6** and gained a `launch` resolver, so a library plugin can answer the host at launch time without standing up its own UI server. `pf-console-ui` gained two `Platform` arms, `Web` and `WebOS`, which an embedder switching on that enum must handle.
